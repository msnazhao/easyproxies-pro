# 按出口 IP 路由

在 `pool` 或 `hybrid` 主入口启用会话路由后，可使用 `用户名._ip_8.8.8.8` 指定 IPv4 出口。IPv6 后缀用短横线表示冒号，例如 `用户名._ip_2606-4700--1111`。会话路由页面接受常规 IP 写法并生成链接，密码沿用主入口配置。

## 选路与异常处理

| 情况 | 行为 |
| --- | --- |
| 同一出口 IP 有多个健康节点 | 按最新探测延迟选择。TCP 和 UDP 均按协议能力过滤。 |
| 节点拨号失败 | 服从代理池重试开关与次数上限。同一次连接最多尝试每个节点一次，全部尝试共享 10 秒拨号时限。 |
| 无同 IP 候选、探测结果过期、候选均已尝试 | 连接失败。所有尝试都限定在指定 IP 内。 |
| `_ip_` 后缀无效 | 认证或生成链接时拒绝。 |
| 拨号期间记录失效或变更 | 关闭刚建立的连接，再在剩余时限内尝试同 IP 的其他候选。 |
| 出口复核服务超时 | 保留上次确认时间，按原时间到期。 |
| 两个服务观察到不同出口 | 立即撤销该节点的出口确认，暂停按 IP 选路。 |

节点身份继续使用稳定的 URI 标识。出口 IP 用于每次新连接的筛选，普通命名会话继续按节点身份绑定。当出口发生变化时，清除旧 IP 对应的地理和 AbuseIPDB 信息，并丢弃旧 IP 的迟到查询结果。已建立的连接由原上游继续处理。探测结果反映探测站点看到的出口，按目的地分流的上游仍可能向业务站点使用不同地址。

## 检测负载

- 启动时逐个检查节点健康状况。每个节点首次通过健康检查后，立即安排出口发现。热重载按节点连接身份保留出口记录和最近一次成功的健康检查结果。每 5 分钟的周期检查覆盖仍有连接或最近一轮内处理过连接的节点。
- 出口 IP 需要两处探测结果一致。进程最多同时运行 16 个出口探测任务，同一节点同一时间最多一次查询。复测由实际代理流量触发，同一节点的探测间隔至少 15 分钟。`/sub/proxies2` 保留最近一次健康检查通过且出口已验证的节点。出口确认超过 30 分钟的固定 IP 会话在拨号前复核，同节点并发请求共用一次复核。
- 成功刷新订阅后，从所有订阅中消失且最后一次健康检查通过的节点留在代理池，并单独存入 `nodes.txt.retained`。自定义 `nodes_file` 时，在该路径后追加 `.retained`。后续刷新会清除已拉黑或已确认不可用的保留节点。重启会加载此来源，重新出现在订阅中的节点按连接身份去重。
- AbuseIPDB 按出口 IP 共享结果。成功结果保留 24 小时，失败后 1 小时内复用失败状态。活跃节点定期检查缓存，IP 变化后按新 IP 取分。首次发现仍可为现有 ISP 选路收集评分。
- 严格路由根据已验证的记录选路。普通代理流量成功使用空闲节点后，可在后台安排出口复测。
