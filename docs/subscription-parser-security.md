# 订阅解析安全审查

## 范围与结论

审查覆盖 Clash YAML 的控制字符兼容、标准解析器调用、节点转换前校验、错误日志及资源限制。没有发现此路径会执行 YAML 中的脚本、自定义对象构造器或本地文件加载指令。订阅作为不可信数据解析；这不构成对订阅来源、节点安全性或所有未知漏洞的保证。

实际响应中的非法字符位于三个节点的 SNI 中。兼容逻辑仅恢复文档的可解析性：显示名称允许清理，连接数据受污染时整条节点跳过，不修复密码、SNI、地址等连接参数。整体结构错误和全部节点不可用时，刷新仍保留旧配置。

## 发现及修复

- 编码绕过：YAML `!!binary` 可在解码后生成 NUL 等控制字符，绕过仅检查原始标量的校验。现在拒绝二进制和自定义标签，并拒绝连接数据中的换行、制表符等控制字符。
- 别名资源消耗：仅限制唯一节点数不能约束展开规模。现在通过记忆化计算估算展开量，逐节点限制为 4096 个展开节点、256 KiB 展开文本及 128 层检查深度，拒绝循环；普通合并别名保持可用。标准 YAML 解析器自身的深度和别名保护也保留。
- 日志泄露：解码错误、未知锚点错误和不支持的节点日志可能包含订阅原始值。现在仅记录节点序号与固定错误类别，不记录名称、字段原值、凭据或原文。
- 日志放大：每份订阅最多记录十条逐节点警告，之后仅保留抑制提示及累计跳过数量，避免大量坏节点放大日志量。
- 凭据误改：清理带锚点的名称时，不能修改其他字段引用的同一个标量。清理前复制节点，受污染的别名连接字段仍被拒绝。
- 标记碰撞：隔离标记避开原文以及 Unicode 转义中的合法字符，避免将合法密码误判为污染数据。
- 输入大小：HTTP 响应以及直接解析入口均限制为 10 MiB。兼容处理不放宽任意 YAML 语法错误或非法 UTF-8。
- 输出放大：多个节点可以引用同一个长密码，原始文档很小但生成的 URI 总量很大。生成的 URI 与名称累计也限制为 10 MiB，超限拒绝本次解析，保留旧节点。

## 验证

`internal/config/clash_security_test.go` 包含危险标签、二进制控制字符、换行注入、循环、指数别名、过大/过深输入、日志保密性和合法合并别名回归测试。它们随常规 `go test ./...` 执行。

`FuzzClashSubscriptionRecovery` 提供模糊测试入口，输入限制为 64 KiB，以测试解析失败路径是否产生崩溃等问题。可执行：

```sh
go test ./internal/config -run '^$' -fuzz FuzzClashSubscriptionRecovery -fuzztime 20s -parallel 2
```

实测 HTTP 订阅会动态变化；使用程序同样的 User-Agent 抓取时，该快照包含 821 个节点，兼容解析保留 817 个，跳过三个 SNI 污染节点和一个字段类型错误节点。

HTTP 订阅内容没有传输加密保护，可能被篡改。解析器加固不能验证订阅提供者或代理节点是否值得信任。
